# MCP and CLI differences

This is the capability inventory for replacing Paseo's MCP feature with an enriched CLI. The migration must preserve the agent workflows currently available through MCP, including their arguments, caller context, result data, and side effects.

Baseline: local `dev` checkout at `b48df9e24`, package version `0.11.2`. The inventory was checked against source implementations and the instantiated CLI command tree. Live daemon operations were not exercised. Proposed migration work below is not implemented or runtime-verified by this document.

The CLI and MCP overlap substantially, but neither is a superset. MCP exposes richer runtime settings, profiles, browser automation, voice output, and completion notifications. CLI adds host administration, imports, streaming, blocking waits, hard deletion, and heartbeat updates.

## Migration checklist

These are capability requirements, not settled command names. Resolve each gap through implementation and verification, or record an explicit decision to retire it before removing MCP.

- [ ] Expose every browser operation listed below, including screenshots, uploads, JavaScript evaluation, workspace/tab selection, and stale-reference errors.
- [ ] Expose voice output with caller-scoped routing, cancellation, and completion after playback.
- [ ] Add saved-profile discovery with notes and complete launch settings.
- [ ] Add provider capability inspection using draft settings and directory context; keep installation diagnostics distinct.
- [ ] Add provider feature values at agent creation and update; add model updates and explicit model/thinking resets.
- [ ] Support metadata and runtime changes in one update, or document a deliberate replacement sequence and its partial-failure behavior.
- [ ] Support mode selection as part of prompt dispatch, preserving ordering before the prompt runs.
- [ ] Preserve finish/error/permission notifications for asynchronous create/send, including an explicit opt-out and caller identity. `--no-wait` alone does not establish this contract.
- [ ] Expose a session-close operation that preserves history; do not substitute hard deletion for `kill_agent`.
- [ ] Add agent listing by directory, status set, result limit, and archived activity age, with independent archived/background inclusion.
- [ ] Preserve complete agent snapshots, normalized permissions, provider/model/profile data, and curated activity in machine-readable output where existing CLI projections omit information.
- [ ] Add permission response fields for `selectedActionId` and `updatedPermissions`, preserving single-request targeting alongside CLI bulk operations.
- [ ] Add schedule worktree isolation and deliberate caller-runtime inheritance, covering provider, model, mode, thinking, features, and other inherited configuration.
- [ ] Add explicit schedule model/mode clearing and retain existing limit/expiry clearing behavior.
- [ ] Preserve workspace ownership, parentage, directory defaults, background inheritance, and workspace notification policies for CLI calls made inside agents and from external clients.
- [ ] Review policy and authorization behavior when replacing tool-catalog restrictions with shell-accessible commands. Preserve actual host permission checks.
- [ ] Audit legacy MCP creation shapes and hidden CLI compatibility paths; migrate consumers or explicitly retire those contracts.
- [ ] Audit provider-native tool delivery as well as MCP transport, shared command services, injected instructions, configuration, and external MCP clients before deleting code.
- [ ] Verify CLI replacements at the cheapest reliable layer: unit tests for parsing/defaults, contract tests for RPC/context/results, and a small number of end-to-end agent/browser/voice journeys.
- [ ] Complete the documentation and skill migration below, including removal of obsolete Paseo MCP references and verification of replacement examples.
- [ ] Run required repository checks and record the remaining live verification before removal.

## Conventions and source map

CLI entries omit the `paseo` prefix. MCP arguments marked `?` are optional. CLI flags take values where their names imply a value; boolean switches are called out in context. "No counterpart" means no dedicated exposed action, not that the behavior is impossible through arbitrary shell commands or configuration edits.

### Listing differences

| Behavior                      | MCP                                                                                      | CLI                                                                                                                                 |
| ----------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Default scope                 | Caller directory and descendants when agent-scoped; no directory restriction externally  | Active workspace scope; `--global` broadens it                                                                                      |
| Archived/background inclusion | Independent `includeArchived` and `includeBackground`                                    | `--all` includes both archived and background agents and removes the default active scope; `--background` includes background alone |
| Result limit                  | Default 50; maximum 200                                                                  | No exposed limit flag                                                                                                               |
| Age filter                    | `sinceHours`, default 48, maximum 720; implementation applies it only to archived agents | No exposed age filter                                                                                                               |
| Status filter                 | `statuses[]`                                                                             | No registered `--status` flag                                                                                                       |
| Directory filter              | `cwd`                                                                                    | No registered `--cwd` flag on `ls`                                                                                                  |
| Labels/thinking               | Not exposed                                                                              | `--label`, `--thinking`                                                                                                             |

CLI internal types mention status and directory filtering, but command registration does not expose those flags. Sources: [MCP catalog](../packages/server/src/server/agent/tools/paseo-tools.ts), [CLI listing](../packages/cli/src/commands/agent/ls.ts).

## MCP-only browser and voice actions

All tab-scoped browser tools require `browserId`; the argument column omits that repeated field. `browser_list_tabs` and `browser_new_tab` do not take `browserId`.

| --------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `browser_list_tabs`                                 | None                                           | Lists workspace tabs across connected browser hosts.                                           |
| `browser_new_tab`                                   | `url?`                                         | Creates a background tab on the most recently connected browser host.                          |
| `browser_snapshot`                                  | None                                           | Returns readable page state and element references.                                            |
| `browser_navigate`                                  | `url`                                          | HTTP(S) navigation; scheme-less host URLs become HTTP.                                         |
| `browser_back`, `browser_forward`, `browser_reload` | None                                           | History navigation and reload.                                                                 |
| `browser_click`                                     | `ref`, `button?`, `doubleClick?`, `modifiers?` | Single left click by default; buttons are left/right/middle, modifiers Alt/Control/Meta/Shift. |
| `browser_fill`                                      | `ref`, `value`                                 | Fills an input-like element.                                                                   |
| `browser_type`                                      | `text`, `ref?`                                 | Types into a specified or focused element.                                                     |
| `browser_keypress`                                  | `key`, `ref?`                                  | Sends a keypress.                                                                              |
| `browser_hover`                                     | `ref`                                          | Hovers over an element.                                                                        |
| `browser_select`                                    | `ref`, `value`                                 | Selects an option.                                                                             |
| `browser_drag`                                      | `sourceRef`, `targetRef`                       | Drags one element onto another.                                                                |
| `browser_upload`                                    | `ref`, nonempty `filePaths[]`                  | Sets workspace files on a file input.                                                          |
| `browser_wait`                                      | Exactly one of `text` or `url`; `timeoutMs?`   | Waits for text or URL matching; default 5 seconds, maximum 30 seconds.                         |
| `browser_screenshot`                                | `fullPage?=false`                              | Returns a PNG screenshot. CLI replacement needs a usable image artifact/output contract.       |
| `browser_logs`                                      | `maxEntries?=50`, maximum 200                  | Console messages and performance network entries.                                              |
| `browser_evaluate`                                  | `function`, `ref?`                             | Evaluates JavaScript; optionally passes the referenced element.                                |
| `browser_scroll`                                    | `deltaX`, `deltaY`, `ref?`                     | Scrolls in CSS pixels.                                                                         |
| `browser_resize`                                    | Positive integer `width`, `height`             | Resizes the resident webview viewport.                                                         |

Browser registration requires browser tooling to be enabled and a broker to be available; execution needs a connected browser host. Listing/creating tabs requires workspace context. Element references such as `@e1` belong to the same tab's latest snapshot and can expire. Preserve explicit stale-reference and host-unavailable failures.

`speak` requires an agent-scoped session with a voice handler and receives cancellation through the execution signal. CLI `speech` is currently an empty command group, not a replacement.

## Removal boundary and verification

The MCP server registers the shared Paseo tool catalog. Public documentation also describes provider-native delivery of these capabilities. Removing the transport, removing injected tools, and removing the shared services are different changes. Trace their consumers before deciding which code can be deleted. Preserve services still used by CLI, RPC, the app, or provider integrations.

For each migration checklist item, record the replacement command, accepted inputs, caller/default behavior, output fields, failure behavior, and verification evidence. A CLI parser accepting an option proves only argument availability. Live/browser/voice behavior needs the corresponding integration proof.

Use fast unit tests for option validation, nullable resets, selection, and inheritance rules. Use fewer contract tests for RPC payloads, notifications, permissions, and output serialization. Keep end-to-end coverage focused on representative delegation, browser, and voice workflows; do not repeat detailed input matrices at that layer.

Known reference mismatches to resolve while migrating:

- Some CLI quick-start examples omit a provider, but current run/schedule parsing requires one at runtime.
- `list_agents` describes recent agents, but its age filter only filters archived entries.
- `kill_agent` says it terminates permanently, but runtime closure preserves the stored snapshot.
- Public MCP documentation omits notification-rule tools present in the source catalog.

Reference docs: [MCP](../public-docs/mcp.md), [CLI](../public-docs/cli.md), [schedules](../public-docs/schedules-cli.md). Treat implementation and verified behavior as the baseline when those pages disagree.
